  <threat id="T-2-AppleAud" severity="high" stride="Spoofing">
    <description>Re-stated from plan 02 threat model — the handler layer is responsible for converting `apple.Verifier.Verify` errors to HTTP 401, not 500. If the handler returns 500 on audience mismatch, an attacker probing audience values can distinguish "wrong aud" from "wrong sig" via timing or by-feature-flag differences, narrowing the attack surface.</description>
    <mitigation>Per D-27: the handler maps ANY error from `verifier.Verify` to HTTP 401 with body `{"error":"invalid identity token"}` (single canonical string — no leak of parser internals per HOTFIX-04). The verifier returns `errors.New("apple: audience mismatch")` and the handler does NOT branch on the error message — it returns 401 uniformly.</mitigation>
    <verification>Test `TestAppleSignIn_AudienceMismatch_Returns401` injects a fake verifier that returns an error; asserts response status is 401 and body has the generic message.</verification>
  </threat>
  <threat id="T-2-EmailBodySpoof" severity="high" stride="Spoofing">
    <description>D-20 allows the request body to carry an `email` field on first Apple sign-in (Apple sends email only on the very first auth; subsequent sign-ins return only `sub`). An attacker could forge this body field — e.g. `{"identityToken":"<valid token without email>", "email":"victim@example.com"}` — hoping the handler trusts the body field and uses it as an auto-link key against the verified-email partial index. If trusted, this is a one-shot account-takeover.</description>
    <mitigation>The handler MUST prefer the JWT's `email` claim when present. If the JWT email is empty, the request-body email is used ONLY for storage in the new row (not for auto-link lookup). Auto-link via `FindUserByVerifiedEmailForLink` is performed only with the JWT email AND only when `identity.EmailVerified=TRUE AND identity.IsPrivateRelay=FALSE`. The request-body `email` is NEVER passed to `FindUserByVerifiedEmailForLink` — explicitly documented in code comment + verified by test `TestAppleSignIn_BodyEmailNeverUsedForAutoLink`.</mitigation>
    <verification>Code grep: the only call to `FindUserByVerifiedEmailForLink` in the new code receives `identity.Email` (verifier output), NOT `req.Email`. Dedicated test asserts: a token without email + a body field `email="victim@example.com"` + a victim row matching that email → response returns a NEW row, NOT the victim's row.</verification>
  </threat>
  <threat id="T-2-GuestJWTSpoof" severity="high" stride="Spoofing">
    <description>The optional `Authorization: Bearer` header signals guest-promotion intent. If the handler accepts any JWT-shaped string without HS256 signature verification, an attacker can spoof a guest_user_id, causing the handler to UPDATE the victim's `users` row instead of creating a new SSO row — full account takeover.</description>
    <mitigation>Per D-27, the Authorization header (when present) MUST be parsed via `jwt.ParseWithClaims(token, &claims, keyFunc(cfg.JWTSecret), jwt.WithValidMethods([]string{"HS256"}))`. Signature failure → return 403 immediately, do NOT fall through to "no guest promotion" path (which would treat the request as a fresh sign-in and silently create a new row, hiding the attempted attack from the user). Test `TestAppleSignIn_InvalidGuestJWT_Returns403` covers this.</mitigation>
    <verification>Test asserts: presenting `Authorization: Bearer evil.tampered.token` returns HTTP 403, NOT 200 with a new row.</verification>
  </threat>
  <threat id="T-2-RelaySkip" severity="high" stride="Spoofing">
    <description>Re-stated from plan 04 threat model at the handler layer. The handler is responsible for never passing a private-relay email to the auto-link function. Even though the repo function defends in depth, the handler MUST gate the call.</description>
    <mitigation>Auto-link branch in handler: `if identity.EmailVerified && !identity.IsPrivateRelay { existing, err := repo.FindUserByVerifiedEmailForLink(db, identity.Email); ... }`. The conditional guard means the repo function is never invoked with a private-relay address. Test `TestAppleSignIn_PrivateRelaySkipsLink` asserts: a token with IsPrivateRelay=true + an existing row with matching email_verified=true returns a NEW row.</mitigation>

  </threat>

// mintGuestJWT returns a valid HS256 token whose sub is userID — used by guest-promotion tests.
func mintGuestJWT(t *testing.T, secret, userID string) string {
	t.Helper()
	claims := jwt.MapClaims{
		"sub":  userID,
		"tier": "free",
		"role": "user",
		"name": "",
		"iat":  time.Now().Unix(),
		"exp":  time.Now().Add(5 * time.Minute).Unix(),
	}
	tok := jwt.NewWithClaims(jwt.SigningMethodHS256, claims)
	s, err := tok.SignedString([]byte(secret))
	if err != nil {
		t.Fatalf("mint guest jwt: %v", err)
	}
	return s
}

// googleVerifier is the matching interface for GoogleSignIn.
type googleVerifier interface {

type appleSignInRequest struct {

// parseGuestJWT decodes and verifies an optional Authorization: Bearer guest JWT.
// Returns the guest user_id when valid, "" when the header is absent, or an
// error when the header is present but malformed/invalid-sig (T-2-GuestJWTSpoof).
func parseGuestJWT(authHeader, secret string) (string, error) {
	if authHeader == "" {
		return "", nil
	}
	tokenString := strings.TrimPrefix(authHeader, "Bearer ")
	if tokenString == authHeader {
		// Header didn't start with "Bearer " — treat as absent.
		return "", nil
	}
	claims := jwt.MapClaims{}
	_, err := jwt.ParseWithClaims(tokenString, claims, func(t *jwt.Token) (interface{}, error) {
		return []byte(secret), nil
	}, jwt.WithValidMethods([]string{"HS256"}))
	if err != nil {
		return "", err
	}
	sub, _ := claims["sub"].(string)
	if sub == "" {
		return "", errors.New("guest jwt: missing sub")
	}
	return sub, nil
}

// resolveSSOUser encapsulates the FindOrCreate-with-race-fallback pattern
// shared between Apple and Google sign-in flows. Returns the resolved user.
//
// Composition (per RESEARCH.md §Account-Linking Race Condition + §Guest-Promote-in-Place):
//   Step A: findByProvider(sub) — does a row already own this sub?
//           If yes AND guestUserID is set + different → reassign guest's devices
//           to the existing row and orphan the guest user, inside db.Transaction
//           (D-06). Return the existing row.
//   Step B: try auto-link by verified email (D-03/D-04 — only when email_verified
//           AND !is_private_relay).
//   Step C: if no auto-link candidate → if guestUserID set, PromoteGuestToSSO
//           (D-06 in-place). Else CreateUser with the provider sub set; on
//           ErrDuplicate re-read via findByProvider (race lost — W-4 fallback
//           keeps every concurrent caller on the 200 path).
type ssoResolveParams struct {
	provider       string // "apple" or "google"
	sub            string
	email          string
	emailVerified  bool
	isPrivateRelay bool
	fullName       string
	guestUserID    string // "" if no guest-promotion attempt
}

// findUserByProviderID dispatches between FindUserByAppleID and FindUserByGoogleID.
func findUserByProviderID(db *gorm.DB, provider, sub string) (*model.User, error) {
	switch provider {
	case "apple":
		return repository.FindUserByAppleID(db, sub)
	case "google":
		return repository.FindUserByGoogleID(db, sub)
	default:
		return nil, fmt.Errorf("unknown provider %q", provider)
	}
}

func resolveSSOUser(db *gorm.DB, logger *zap.Logger, p ssoResolveParams) (*model.User, error) {
	// Step A: does a row already own this provider sub?
	existing, err := findUserByProviderID(db, p.provider, p.sub)
	if err != nil && !errors.Is(err, repository.ErrNotFound) {
		return nil, err
	}
	if existing != nil {
		// D-06 reassign-and-orphan branch (B-3 fix): if a guest JWT is presented
		// alongside a sub that's already owned, move the guest's devices to the
		// existing row and delete the (now-stale) guest user row. Both writes
		// happen inside a single db.Transaction so neither can leak partial state.
		if p.guestUserID != "" && p.guestUserID != existing.ID {
			txErr := db.Transaction(func(tx *gorm.DB) error {
				if _, rErr := repository.ReassignDevicesByUserID(tx, p.guestUserID, existing.ID); rErr != nil {
					return fmt.Errorf("reassign devices: %w", rErr)
				}
				if dErr := repository.DeleteOrphanGuestUser(tx, p.guestUserID); dErr != nil &&
					!errors.Is(dErr, repository.ErrNotFound) {
					return fmt.Errorf("delete orphan guest: %w", dErr)
				}
				return nil
			})
			if txErr != nil {
				// Log and return 500 — partial state is impossible (tx rolled back).
				logger.Error("sso: reassign-and-orphan tx failed",
					zap.String("guest_user_id", p.guestUserID),
					zap.String("existing_user_id", existing.ID),
					zap.Error(txErr))
				return nil, txErr
			}
		}
		return existing, nil
	}

	// Step B: try auto-link by verified email (D-03/D-04).
	if p.email != "" && p.emailVerified && !p.isPrivateRelay {
		linkCandidate, lerr := repository.FindUserByVerifiedEmailForLink(db, p.email)
		if lerr != nil && !errors.Is(lerr, repository.ErrNotFound) {
			return nil, lerr
		}
		if linkCandidate != nil {
			// Attach the new provider's column to the existing row.
			updates := map[string]interface{}{}
			switch p.provider {
			case "apple":
				updates["apple_user_id"] = p.sub
			case "google":
				updates["google_user_id"] = p.sub
			}
			updates["auth_provider"] = p.provider
			if err := db.Model(&model.User{}).Where("id = ?", linkCandidate.ID).Updates(updates).Error; err != nil {
				// B-2 fix: errors.Is against the public sentinel — the private
				// repository.isDuplicateError helper is unreachable from this package.
				if errors.Is(err, repository.ErrDuplicate) {
					// Race — re-read.
					return findUserByProviderID(db, p.provider, p.sub)
				}
				return nil, err
			}
			// Re-read to get the merged row.
			return repository.FindUserByID(db, linkCandidate.ID)
		}
	}

	// Step C: no existing row, no auto-link. Either promote the guest in place or create new.
	if p.guestUserID != "" {
		err := repository.PromoteGuestToSSO(db, p.guestUserID, p.sub, p.email, p.provider, p.isPrivateRelay)
		if err != nil {
			if errors.Is(err, repository.ErrDuplicate) {
				// Race lost — another request grabbed this sub. Re-read.
				return findUserByProviderID(db, p.provider, p.sub)
			}
			if errors.Is(err, repository.ErrNotFound) {
				// Guest row vanished — fall through to create.
			} else {
				return nil, err
			}
		} else {
			return repository.FindUserByID(db, p.guestUserID)
		}
	}

	// Step D: create a new SSO row.
	newUser := &model.User{
		FullName:            p.fullName,
		SubscriptionTier:    "free",
		Role:                "user",
		AuthProvider:        p.provider,
		EmailVerified:       p.emailVerified,
		EmailIsPrivateRelay: p.isPrivateRelay,
	}
	if p.email != "" {
		newUser.Email = &p.email
	}
	switch p.provider {
	case "apple":
		newUser.AppleUserID = &p.sub
	case "google":
		newUser.GoogleUserID = &p.sub
	}
	if err := repository.CreateUser(db, newUser); err != nil {
		// W-4: every concurrent caller funnels through this branch — the
		// re-read on ErrDuplicate is what keeps the response 200 instead of 500.
		if errors.Is(err, repository.ErrDuplicate) {
			return findUserByProviderID(db, p.provider, p.sub)
		}
		return nil, err
	}
	return newUser, nil
}

// AppleSignIn handles POST /api/v1/auth/apple.
//
// Flow per D-19 / D-20: parse → verify → resolveSSOUser → generateTokens →
// storeRefreshSession → respond. Optional Authorization: Bearer signals
// guest-promotion intent (D-06).
//
// Error mapping (D-27):
//   400 — malformed/missing identityToken
//   401 — verifier error (any kind: sig, aud, exp, iss)
//   403 — invalid guest JWT
//   500 — internal (DB, generateTokens, storeRefreshSession failures)
func AppleSignIn(logger *zap.Logger, cfg *config.Config, db *gorm.DB, verifier appleVerifier) fiber.Handler {
	return func(c *fiber.Ctx) error {
		var req appleSignInRequest
		if err := c.BodyParser(&req); err != nil || req.IdentityToken == "" {
			return c.Status(fiber.StatusBadRequest).JSON(fiber.Map{"error": "identityToken is required"})
		}

		// Optional guest-promotion JWT in Authorization header.
		guestUserID, err := parseGuestJWT(c.Get("Authorization"), cfg.JWTSecret)
		if err != nil {
			return c.Status(fiber.StatusForbidden).JSON(fiber.Map{"error": "invalid guest token"})
		}

		identity, err := verifier.Verify(c.Context(), req.IdentityToken)
		if err != nil {
			logger.Info("apple verify failed", zap.Error(err))
			return c.Status(fiber.StatusUnauthorized).JSON(fiber.Map{"error": "invalid identity token"})
		}

		// SECURITY (T-2-EmailBodySpoof): NEVER trust the request body's `email` field as
		// an auto-link key. Auto-link lookup uses `identity.Email` (from the verified JWT).
		// The body `Email` is used ONLY to populate `fullName` and as a fallback display
		// value on first-sign-in for non-Apple-supplied fields; it is not passed to
		// FindUserByVerifiedEmailForLink anywhere in this handler.
		_ = req.Email

		user, err := resolveSSOUser(db, logger, ssoResolveParams{
			provider:       "apple",
			sub:            identity.Sub,
			email:          identity.Email,
			emailVerified:  identity.EmailVerified,
			isPrivateRelay: identity.IsPrivateRelay,
			fullName:       req.FullName,
			guestUserID:    guestUserID,
		})
		if err != nil {
			logger.Error("apple signin: resolve user", zap.Error(err))
			return c.Status(fiber.StatusInternalServerError).JSON(fiber.Map{"error": "internal server error"})
		}

		tokens, err := generateTokens(user.ID, user.SubscriptionTier, user.Role, user.FullName, cfg.JWTSecret)
		if err != nil {
			logger.Error("apple signin: generate tokens", zap.Error(err))
			return c.Status(fiber.StatusInternalServerError).JSON(fiber.Map{"error": "internal server error"})
		}
		if err := storeRefreshSession(db, user.ID, tokens.RefreshToken); err != nil {
			logger.Error("apple signin: store refresh", zap.Error(err))
			return c.Status(fiber.StatusInternalServerError).JSON(fiber.Map{"error": "internal server error"})
		}

		return c.JSON(fiber.Map{"data": ssoResponseBody(user, tokens)})
	}
}

// ssoResponseBody builds the `data` portion of the SSO response (D-21).

			"email":             email,
			"full_name":         user.FullName,
			"subscription_tier": user.SubscriptionTier,

	}
}
