<objective>
Implement per-user VLESS UUIDs with REAL tunnel-side wire enforcement (HARD-02 / S4-2, S5-1, SC#2): each user gets a distinct UUID per server, rotated on plan change, and the tunnel REJECTS any UUID not provisioned for the presenting user. API is source of truth; the tunnel pulls the active UUID set over the existing heartbeat channel, debounces, regenerates the xray config and reloads (D-05). Because xray-core has no hot reload, the reload is connection-dropping — it MUST be debounced/batched with a documented 30-60s propagation floor (NOT "seconds" for the wire).

**SC#2 "rotates" propagation floor (verifier note):** the API rotates the UUID *immediately* (new identity row active, old `is_active=false` in the same tx), but the WIRE enforcement lags one reload cycle = heartbeat interval (>=30s) + debounce (5-10s) = a realistic **30-60s** floor. SC#2's "rotates" is therefore satisfied at the API instantly and at the wire within 30-60s — the verifier must accept the wire result against that documented floor, not demand sub-second wire enforcement (xray-core has no hot reload).

Purpose: Close the highest-weight audit finding (shared VLESS UUID lets any user reach any server / enumerate the fleet) at the wire, not just in the API response.
Output: Migration 026, vless repo + model, API allocation/rotation + active-set endpoint, tunnel ReloadClients + debounced pull loop, and the wire-level rejection harness validated.
</objective>
