  <action>
Create `.github/workflows/ci.yml` triggered on `pull_request` touching `server/**`, with two jobs (api + tunnel) so each module is scanned with its own go.mod:
```yaml
name: CI
on:
  pull_request:
    paths: ['server/**']
jobs:
  govulncheck-api:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: golang/govulncheck-action@v1
        with:
          go-version-file: server/api/go.mod
          work-dir: server/api
  govulncheck-tunnel:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: golang/govulncheck-action@v1
        with:
          go-version-file: server/tunnel/go.mod
          work-dir: server/tunnel
```
The official `golang/govulncheck-action@v1` exits non-zero on findings by default — this is the blocking behavior SC#3 wants. At implementation time, VERIFY the action's current README still defaults to fail-on-findings (assumption A2); if a flag is required, set it explicitly. Add a comment documenting that suppression of an unfixable advisory = upgrade/replace the dep (the action has no built-in silencing); only as a last resort run `govulncheck` directly with an explicit allowlist comment.
