<threat_model>
  <threat id="T-1-02" severity="high" category="Elevation of Privilege">
    <description>An admin demoted via the admin panel (UPDATE users SET role='user') continues to hold full admin privileges for the remaining JWT lifetime — up to 5 minutes for the access token, longer if rotation just happened — because AdminRequired trusts the role claim in the JWT rather than checking the current database row. A compromised or rogue admin can keep using their access token after the operator believes they have revoked privileges.</description>
    <mitigation>Task 2 replaces the JWT-claim check in middleware.AdminRequired with a per-request `repository.FindUserByID` lookup that reads the current `Role` value from the users table. No Redis cache, no TTL — pure DB read every time. ROADMAP success criterion #1 explicitly requires the change to be effective on the "very next request"; any cache TTL > 0 would violate this. The cost is bounded by admin traffic volume (< tens of req/min today; PERF-04 in Phase 6 will add a ≤5s cache once the system grows).</mitigation>
    <verification>Acceptance criteria in Task 2: integration test `TestAdminRequired_DemotionTakesEffect` flips 200 → 403 with the same JWT after the underlying DB row is demoted. Smoke from plan 09 step 4 verifies on staging.</verification>
  </threat>
</threat_model>
