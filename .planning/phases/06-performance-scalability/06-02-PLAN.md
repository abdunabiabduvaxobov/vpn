<objective>
Implement PERF-05 (`idx_connections_heartbeat_active` partial index) and PERF-08 (`idx_connections_connected_at` index) as migrations 022/023, and fold in the COALESCE-drop on the stale-connection sweep predicate so the planner can range-scan the new partial index (research Fork 2 confirmed this is safe — active rows always have a non-null `last_heartbeat_at`).

Both indexes use `CREATE INDEX CONCURRENTLY IF NOT EXISTS` — proven safe through the existing `docker-entrypoint-initdb.d` runner (migration 017 already does this; the test harness special-cases CONCURRENTLY via `splitSQLStatements`). The CONCURRENTLY + IF NOT EXISTS form makes the files idempotent so they are safe whether applied by initdb (fresh volume) or by a manual online backfill (live DB — see plan 06's runbook task).

Purpose: keeps the stale-connection sweep O(connected) not O(history), and keeps admin analytics fast as the connections table grows to millions of rows (audit §2.2, §2.3).
Output: two migration files + a one-line predicate rewrite, proven by the Wave 0 EXPLAIN test (D-09 assertion (a)).
</objective>
