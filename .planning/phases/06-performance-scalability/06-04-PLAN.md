## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-USERCACHE | Elevation of Privilege | user:<id> entitlement cache | mitigate | A downgraded/expired/deleted user must never keep Pro/admin past a mutation. Two-layer bound: (1) synchronous BustUserCache on EVERY mutation path (admin update, webhook grant, delete/restore, BOTH bulk downgrades via RETURNING id), and (2) TTL ≤ 5s as a backstop. role/tier for AUTHZ still come from the JWT claim (5-min TTL) + the existing AdminRequired DB re-read (HOTFIX-02) — the user cache only fronts the EXISTENCE gate, so a stale cache cannot grant admin. Asserted by TestUserCache (bust → miss → DB authoritative). |
| T-06-USERCACHE-FAILOPEN | DoS / availability | Redis outage on AuthRequired | mitigate | GetUserCache returns found=false on outage → AuthRequired falls through to the existing DB existence check. No request path breaks; the deleted-user 401 guard still fires from the DB. |
| T-06-WEBHOOK-IDEMP | Tampering (replay) | webhook bust on Pro-grant | mitigate | Bust is on the SUCCESS side-effect path only; a duplicate event short-circuits on the lava_webhook_events UNIQUE and neither re-applies nor re-busts. The 200/500 contract (return 500 so lava retries) is unchanged — a bust error logs but still returns 200. The existing idempotency guarantee is not weakened. |
| T-06-USERKEY | Tampering | cache key from input | accept | Key is `user:<uuid>` where uuid is the validated JWT sub / path id — no raw client string interpolated. |

T-06-USERCACHE is the HIGH-watch item; mitigated to no residual HIGH by the synchronous bust + ≤5s TTL + JWT-sourced authz + AdminRequired DB re-read.
