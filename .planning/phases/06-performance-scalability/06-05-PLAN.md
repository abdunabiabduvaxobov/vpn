<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client heartbeat -> Redis | authenticated; ownership enforced before the Redis write |
| scheduler -> connections (bulk flush + prune) | internal background writes; no untrusted input |
| operator env -> scheduler start | RUN_SCHEDULER controls whether periodic jobs run |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-HB-FAILOPEN | DoS / availability | Redis outage on heartbeat | mitigate | TouchHeartbeat fails open (nil/err returns 204); a missed flush window is bounded by the 3-min StaleConnectionAfter grace; PG stays source-of-truth so a Redis restart costs at most one 10s window. |
| T-06-HB-OWNERSHIP | Spoofing / EoP | heartbeat for another user's conn | mitigate | The FindConnectionByID ownership pre-read is retained (per-request 404/ownership check) before the Redis write — a client cannot refresh a connection it does not own. |
| T-06-SCHED-DOUBLE | Tampering (double-run) | multi-replica scheduler | mitigate | RUN_SCHEDULER gate ensures only the primary replica runs periodic jobs; the flush itself is multi-replica safe (shared dirty set, idempotent UPDATE) as defense-in-depth. |
| T-06-PRUNE | Tampering (data loss) | 90-day connection prune | accept | Deletes only disconnected_at-non-null rows older than 90 days (historical, not active); weekly cadence; bounded by idx_connections_connected_at. Active rows (disconnected_at IS NULL) are never touched. |

No HIGH residual: fail-open + retained ownership check + the single-runner gate cover the heartbeat/scheduler surface.
</threat_model>
