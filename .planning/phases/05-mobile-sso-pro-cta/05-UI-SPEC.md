# Phase 5 — UI Design Contract

> Visual and interaction contract for the React Native mobile app (v2.2.0): LoginScreen, PaymentScreen rewrite, "You're leaving the app" interstitial, Activating-Pro modal with polling, AccountScreen "Sign in to sync Pro" card. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Stack:** React Native 0.84 bare workflow (not Expo) + TypeScript + Zustand + i18next + react-navigation. No design system tool, no component library — RN core primitives styled via centralized tokens at `app/src/theme/`.

## Typography

Codified from `app/src/theme/typography.ts` — **REUSE; do NOT add new sizes**:

| Role | Token | Size | Weight | Line Height | Phase 5 Usage |
|------|-------|------|--------|-------------|---------------|
| Display | `typography.h1` | 32 | 700 | 40 | Modal "Activating your Pro…" title (matches Phase 4 weight); LoginScreen welcome heading |
| Heading | `typography.h2` | 24 | 700 | 32 | PaymentScreen current-plan card title; AccountScreen "Sign in to sync Pro" section title |
| Subheading | `typography.h3` | 20 | 600 | 28 | Card titles (plan name, "Pro includes" header); interstitial sheet title |
| Body | `typography.body` | 16 | 400 | 24 | All body copy (feature bullets, descriptions, button labels via `bodyBold`) |
| Body bold | `typography.bodyBold` | 16 | 600 | 24 | Primary CTA button text, card values |
| Caption | `typography.caption` | 13 | 400 | 18 | Secondary text (interstitial sheet body, timeout body, hint copy, "Already paid? Refresh" link) |
| Caption bold | `typography.captionBold` | 13 | 600 | 18 | Small badges ("Linked", "Most Popular"); stat values |
| Mono | `typography.mono` | 14 | 400 | 20 | Invoice ID display if surfaced (debug only — not in main UI) |

**Scale justification (documented exception to checker's standard 4-size/2-weight ceiling):**

1. **Locked from Phase 1 theme.** The 3-weight (400 / 600 / 700) and 5-size (32 / 24 / 20 / 16 / 13, plus 14 mono) scale above is codified verbatim from `app/src/theme/typography.ts`, a token file established in Phase 1. Per CONTEXT.md `code_context` (lines 217–218): **REUSE, NO NEW TOKENS.**
2. **Powers 8+ existing screens.** This scale already drives the existing RN app (HomeScreen, AccountScreen, PaymentScreen, SubscriptionScreen, ServersScreen, SettingsScreen, OnboardingScreen, and the cross-cutting Toast/Modal primitives among others). Reducing it to fit the checker's 4-size/2-weight ceiling would require a cross-phase refactor of every consuming surface and is **explicitly out of scope for Phase 5**.
3. **`mono` is debug-only.** The `mono` role (14px / 400) is reserved for raw invoice ID surfacing during debug and is **not used in any main UI flow** in Phase 5. The *functional* UI scale that ships to users in Phase 5 is therefore effectively **5 sizes across 7 roles** (h1, h2, h3, body, bodyBold, caption, captionBold).
4. **Phase 5 introduces zero new typography tokens.** Every new surface (LoginScreen, PaymentScreen rewrite, interstitial sheet, Activating-Pro modal, AccountScreen "Sign in to sync Pro" card) consumes only the existing locked roles from the table above. No new sizes, no new weights, no new line-heights.
5. **Acknowledged exception, not an oversight.** This block exists so future checker passes (and reviewers) see that the breach of the >4-size / >2-weight thresholds was a deliberate, documented carry-forward from Phase 1's locked theme — not negligence by the Phase 5 design pass.

**Hard rules:**
- LoginScreen primary CTAs (Apple, Google, Guest) use `typography.bodyBold` on the button label.
- The "Upgrade to Pro at risevpn.com" CTA uses `typography.bodyBold` on the button label.
- The "Already paid? Refresh" affordance uses `typography.caption` with `color: colors.primary` (tertiary text-style link — explicitly NOT a button per D-15).
- Modal titles use `typography.h2` (matches Phase 4 D-22 weight on web); body copy in modal uses `typography.body`.
- Telegram support link in 30s timeout state uses `typography.caption` with `color: colors.primary`.

## Interaction Contract (RN-specific addendum to the standard 6 dimensions)

Locked interaction patterns from CONTEXT.md decisions. Checker MUST verify each is honored in the implementation.

### LoginScreen (D-02)
- Reached via `navigation.navigate('Login')` — NOT a route-gate. Auto-guest path on app launch is preserved (D-01).
- Three CTAs vertically stacked, each full-width with `borderRadius.sm` (8px), `paddingVertical: spacing.md` (16px), separated by `spacing.md` (16px). Apple uses `colors.primary` background; Google uses `colors.primary` background; Guest uses transparent background + `colors.border` outline (visual de-emphasis to discourage guest as default).
- Apple CTA is hidden via `Platform.OS === 'ios'` guard on Android (RN convention).
- Cancellation from native sheet returns to LoginScreen silently (no Alert).

### "You're leaving the app" interstitial (D-12)
- Triggered by tapping the "Upgrade to Pro at risevpn.com" CTA. **MUST appear BEFORE `Linking.openURL`.**
- Form factor: full-screen RN `Modal` with `animationType="slide"` from bottom (planner's discretion may use a true bottom sheet if a sheet lib is already present — none is, so default to `Modal`).
- Layout: title (`typography.h3`) → body copy (`typography.body`, `colors.textSecondary`) → Continue button (`colors.primary`) → Cancel button (outline, `colors.border`).
- Tapping Continue → `Linking.openURL(upgradeUrl)` then dismiss sheet. Tapping Cancel → dismiss sheet (no navigation).
- Scrim: `colors.overlay` (`rgba(0,0,0,0.5)`).

### Activating-Pro modal (D-07, D-08, D-10, D-11)
- Triggered by `deepLink.ts` receiving `vpnapp://payment/success?invoiceId=X` (cold start OR warm foreground) — renders ABOVE any active screen via root-level overlay (`App.tsx` or `RootNavigator` modal-presentation).
- **Modal blocks dismissal during polling** (no tap-outside, no back-button close, no swipe-down). The only way out is success / failure / 30s timeout.
- Polling cadence (verbatim from D-08 / Phase 4 D-21):
  - `GET /api/v1/invoices/:id` every 2000ms.
  - Polls 1–5 (elapsed 0–10s): no query string.
  - Poll 6+ (elapsed ≥10s): append `?escalate=true`.
  - Total budget: 30 seconds (15 polls max).
- States (drive UI from `paymentReturnStore` or `authStore` extension — Claude's Discretion):
  1. **Polling** — spinner + `payment.activating.title` + `payment.activating.subtitle`. Spinner is `ActivityIndicator` size="large" with `color={colors.primary}`. No "Cancel" button.
  2. **Success** (`status === 'paid'`) — close modal, navigate to / stay on Home, present a transient toast (`typography.bodyBold`, `colors.success`) reading `payment.activating.successToast` for ~3s, then auto-dismiss. Also call `authStore.fetchAccount()` before closing modal so Home renders with Pro state on the same frame.
  3. **Failed** (`status === 'failed'`) — show `payment.activating.failedTitle` + `payment.activating.failedBody`, single primary button `payment.activating.failedRetry` → dismiss modal + `navigation.navigate('Account')`.
  4. **Timeout** (30s elapsed, status still pending) — switch to `payment.takingLonger.title` body + `payment.takingLonger.body`. Show `Refresh` button (`colors.primary`) + Telegram support link (`colors.primary` caption-style text) + `Close` button (re-enables dismissal — `colors.border` outline). **No auto-retry from this state.** Refresh tap calls `authStore.fetchAccount()` + a single `GET /invoices/:id?escalate=true`; if response is `paid` → transition to Success; otherwise stay in timeout state.

### Foreground safety-net (D-09)
- Extends existing `HomeScreen.tsx` lines 41–50 `AppState.addEventListener('change')` hook. When transitioning to `active`, ensure it picks up subscription state in addition to calling `fetchAccount`. Implementation detail (single `/account` call sufficient vs. separate `/subscription` call) is the planner's call, but the visible result must be: "user closed browser after paying, opens mobile app, sees Pro on Home within one network roundtrip."
- **No UI change required** — this is a behavioral extension only. AccountScreen's existing `auth_provider`-based "Sign in to sync Pro" card visibility flips off automatically once `fetchAccount` returns the SSO-bound user.

### AccountScreen "Sign in to sync Pro" card (D-03)
- Visible **only when** `user.auth_provider === 'guest'` OR `user.auth_provider` is undefined (v2.1.0 carry-over rows).
- Positioned **above** the existing Subscription card in the ScrollView (highest visual priority for guest users).
- Card styling: `colors.surface` background, `borderRadius.lg` (16px), `spacing.lg` (24px) padding, `colors.border` outline — matches existing AccountScreen card pattern.
- Layout: section title (`typography.bodyBold`, `colors.textPrimary`) → body copy (`typography.caption`, `colors.textSecondary`) → two side-by-side buttons (Apple iOS-only / Google both) with `gap: spacing.sm` (8px), each using `colors.primary` background.
- Tapping either button: `navigation.navigate('Login')` with no params (default — LoginScreen renders all three CTAs). Planner may pass `{provider: 'apple'|'google'}` if direct-invoke UX simulates better.
- Once `user.auth_provider` flips to `apple`/`google`, card unmounts (silent UX per D-05).

### Silent transition on SSO success (D-05)
- No splash screen, no welcome animation, no toast. `authStore` replaces guest tokens with SSO tokens (same `users.id` preserved by backend D-06 in-place promotion); RN navigation pops the LoginScreen and the existing Home screen renders.
- The user perceives this as: tap "Continue with Apple" → native Apple sheet → "Successfully signed in" → app returns to whatever screen they were on (Home if from auto-guest, AccountScreen if from "Sign in to sync Pro").

### Auto-link is silent on success (D-04)
- When backend Phase 2 D-03 auto-links Apple+Google by verified email, **mobile shows no special UI**. The user simply has their existing Pro plan visible on Home / AccountScreen.
- If Apple email is `@privaterelay.appleid.com`, backend D-04 skips auto-link and creates a separate `users.id`. The user discovers this only by missing Pro on the second device — no Phase 5 UI surfaces this case (deferred per D-04 final paragraph).
