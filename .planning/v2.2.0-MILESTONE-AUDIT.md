## Critical Gap (launch blocker)

**Mobile Apple/Google sign-in returns HTTP 400 for every attempt.** The backend SSO request structs use camelCase JSON tags (`json:"identityToken"`, `json:"idToken"`, `json:"deviceId"` — auth.go:751/762/755/763) while the mobile app sends snake_case (`identity_token`, `id_token`, `device_id` — authStore.ts:162/191, pinned by authStore.test.ts:82). Go's `encoding/json` does not bridge underscore-separated names, so the bound fields are empty and the handler 400s with "identityToken is required". The rest of the API correctly uses snake_case (`json:"device_id"` at auth.go:238/367) — the SSO structs are the deviation. **Fix:** change the four SSO struct tags to snake_case (server-side; matches the established convention and the live mobile contract). Affects AUTH-01, AUTH-02, and the entire core-value path.

## Medium Gap

**AdminCancelSubscription does not revoke/rotate the user's VLESS UUID.** A force-cancel is a Pro->system plan change but, unlike the AdminUpdateUser tier-change path (which rotates at admin.go:263), it omits `RotateVlessUUID`/`RevokeAllVlessUUIDs` inside its WithUserLock. The cancelled user's premium-server UUID remains admitted at the wire until the next unrelated reload. **Fix:** add `RevokeAllVlessUUIDs(ctx, tx, userID)` (the function exists at vless_repo.go:120-134, designed for exactly this) inside the cancel lock. Affects HARD-02 wire enforcement.

## Dismissed (auditor false-positive)

`subscription.recurring.payment.success` does not rotate the VLESS UUID — this is **intended** (08-07-PLAN.md:82,151,166 / D-07): a renewal keeps the same plan, and a pure expiry refresh must not churn the user's live connection. Not a gap.
