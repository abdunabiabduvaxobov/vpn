<objective>
Fix the launch-blocking guest-onboarding 500. `users.plan_id` is `uuid NOT NULL`
with no DB default (migration 019). The Go model field `PlanID string
gorm:"...;not null"` has no `default` tag and is not a pointer, so GORM serializes
`plan_id=''` into the INSERT and Postgres rejects it with
`invalid input syntax for type uuid (SQLSTATE 22P02)`. Both `GuestLogin`
(server/api/internal/handler/auth.go) and `createadmin`
(server/api/cmd/createadmin/main.go) call `CreateUser` BEFORE assigning the system
plan_id, so every fresh-user INSERT 500s on any DB where migration 019 has run.
The existing post-insert UPDATE in GuestLogin is dead code.

Purpose: Restore the primary free-tier onboarding path (POST /auth/guest) and admin
bootstrap (createadmin), and guard against regression with a real-Postgres test that
SQLite cannot mask.

Output: PlanID assigned before INSERT in both call sites (single source of truth);
dead post-insert UPDATE removed; new integration test proving guest onboarding works
against real Postgres.

Design constraint (per D-29): the app layer assigns plan_id. Do NOT make the column
nullable, do NOT add a DB default, do NOT change the schema. Keep changes surgical.
</objective>
